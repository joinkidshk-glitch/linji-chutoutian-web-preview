## 3. 融合原則（拍板建議｜標「建議／待用戶 OK」）

1. **【建議】** 小說＝**母本情緒與因果**；遊戲＝**可玩節點＋日常夾層**（通告／訓練／地圖 tip／結算一句）。唔追求「把小說整章塞進 StoryPlay」。  
2. **【建議】** **一章小說 ≠ 一次長播。** 拆成：`觸發場面（短 beats）→ 選擇 → 餘韻（結算 notes／下一節 hint）→ 地圖餘波（tip 熄／轉針、通告板口氣、關係可見）`。  
3. **【建議】** 內心獨白／長場面描寫 → 優先落地為 `playerHint`／`lockedHint`／結算一句／（可選）手帳日誌；**唔硬塞晒入 beats**。Beats 保留「場面建立短＋抉擇對白」。  
4. **【建議】** 茶餐廳／後巷／事務所 → **locId 掛針**（現有 soft loc 可暫用）；播完回地圖必須有**下一節方向**（已有 next／lockedHint 骨架，融合時對齊小說共通段語氣）。  
5. **【建議】** 人情（何生／張子駿／曉晴露面）要喺**遊戲早段可感知**：不只小說有——用地圖人物／meet 漸開／通告旁白／C 節出場，避免「讀完小說先識人、開局世界空」。  
6. **【建議】** 節奏尊重 LIVE pacing：主線之間用日常填滿；日常文案可偷小說氣氛詞（油煙、假菜、名牌鐵夾），但唔另開超長事件。  
7. **【待用戶 OK】** 場景針是否後期補 `cafe_*`／`agent_office`，定長期 soft 掛 `tvb_longmen`／`ad_central`＋文案假裝。  
8. **【待用戶 OK】** 選擇後果：維持短 `effects.notes`，定加 1–2 條 `resultBeats`（仍禁改選擇 id）。

## 6. 拆 JSON 時的拆法規格（等用戶後開刀｜仍唔上 LIVE）

> 僅規格；實作另案。文風跟 `COPY_STYLE_MODERN_v1`＋`COPY_STYLE_HK_LEXICON`（禁自造縮寫／文言腔）。

1. **抽取順序：** 場面建立（≤1–2 beat）→ 推進至抉擇嘅對白（保留聲口）→【選擇】label **唔改 id**（`C1_a`…）→ 後果：優先壓成 `effects.notes` 1 句；需要體感時先草稿 `resultBeats` 1–2（試播後再決定上 LIVE）。  
2. **唔搬：** 大段氣味／回憶散文、選項後 200–500 字全文。改寫成 hint／日誌候補句，放融合表「文案池」，唔當必播 beats。  
3. **共通段：** 對齊「本章之後」→ `nextHint`／日結一句／地圖 tip 文案，令隔日等待有方向。  
4. **場景：** setting 可與小說對齊用字；`locId` 暫跟 LIVE soft；新針另票。  
5. **流程：** 先做 **C1 試作對照表／草稿 JSON（sandbox）** → tester 手感 → 先唔 merge LIVE → 用戶 OK 再逐節。  
6. **禁：** 改選擇 id、改 openConditions／pacing 語義（除非另案 flow）、改 Soft／出圖。
