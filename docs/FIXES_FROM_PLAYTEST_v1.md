## 嚴重問題

### 1. 入門通告門檻過高／核心循環斷層

**現象**  
星河「靈異屋邨夜話」（街坊群戲 ★★）要求演技 90／體能 110／智商 75；中環廣告「街頭路人」要求外貌 90／魅力 100。第 1–2 週全日訓練後演技約 66、智商仍約 20，幾乎全部「暫未能報」。玩家無法完成「先賺穩定收入」的目標。

**根因假設**  
1. 通告門檻表按中後期角色能力設計，未做「週數／進度」分段。  
2. 缺少真正的「零門檻／極低門檻」臨記散工池。  
3. 屬性成長曲線與通告曲線未對齊（尤其智商起點極低）。

**具體改法**

#### A. 加「入門臨記池」（必做）
在第 1–4 週（或 `careerStage === 'rookie'`）保證地圖上至少出現 **2–3 張可報通告**，條件建議：

| 通告名（示例） | 地點類型 | 條件（建議上限） | 報酬／耗日 | 說明 |
|----------------|----------|------------------|------------|------|
| 臨時群演·街景 | 片廠／街頭 | 無，或演技 ≥ 20 | 低薪 +1 日 | 純臨記 |
| 跟組雜務 | 電視台 | 無 | 極低薪 +1 日 | 學環境、微加熟人 |
| 廣告路人 B | 廣告公司 | 外貌 ≥ 30 或 魅力 ≥ 30 | 中低薪 +1 日 | 比現有「街頭路人」低很多 |
| 電台現場觀眾 | 唱片／電台 | 無 | 低薪 + 微魅力 | 拓點 |

實作建議：
- 通告資料加欄位：`minWeek`、`maxWeek`、`tier: 'entry'|'standard'|'featured'`、`req` 物件。
- 刷新通告時：若本週 `tier==='entry'` 可報數量 `< 2`，強制從 entry 池補足。
- UI：entry 通告顯示標籤「入門／臨記」，避免玩家以為全是高門檻。

#### B. 調低現有早期通告門檻（必做）
對 `week <= 4` 或標了 `earlyGame` 的通告做倍率或絕對值下調：

- **建議公式（擇一）**  
  - 絕對：`req' = max(floor(req * 0.45), 屬性基線+10)`  
  - 分段表：第 1–2 週用 `reqTier1`，第 3–4 週 `reqTier2`，第 5+ 用原表  
- 「靈異屋邨夜話」若要留在早期：建議改為演技 45／體能 40／智商 25（或拆成兩階：先「跟組觀摩」再開正式群戲）。  
- 「街頭路人」：外貌 40／魅力 35 左右；原 90／100 移到中後期品牌廣告。

#### C. 對齊成長曲線（強烈建議）
- 列出各訓練每日期望成長（演技／體能／智商／外貌／魅力）。  
- 目標：**正常玩法下第 2 週末至少能報 1 張標準入門通告；第 4 週末能報 1 張 ★★。**  
- 智商若起點 20 且訓練少：要嘛提高相關訓練產出，要嘛早期通告少綁智商。

#### D. 失敗回饋強化（輔助）
已有「差邊項、差幾多」很好；再加：
- 「距離最近可報通告：還差演技 12」  
- 或按鈕「查看可練邊度最快達標」→ 連去訓練地點。

**實作檢查清單**
- [ ] 通告 schema 有 `tier`／週數欄  
- [ ] 第 1 週開新檔：地圖上 ≥ 2 張可報 entry  
- [ ] 第 2 週猛練後，至少 1 張非 entry 亦可報（或 entry 報酬提升）  
- [ ] 高門檻通告仍存在，但標「進階」且 `minWeek` 合理  
- [ ] 經濟：連續 2 週接 entry 不應立刻破產（對照生活費）

**驗收標準**
1. 新手指引路徑下，第 1 週結束前可成功報名並完成 ≥ 1 單通告。  
2. 不靠作弊／改檔，第 3 週前「本週通告完成」不應長期卡在 0／N。  
3. QA 表：列出 week1–4 每週「可報通告數」期望區間（例如 2–5）。

**優先級**：P0

### 2. 「傳聞」拼卡教學卡住、拖放無反應

**現象**  
畫面長駐：「教學開始…按住卡片，拖去對應位置。呢個位仲未啱…」。點卡、拖到標籤或其他卡皆無進展。

**根因假設**
1. drop target hit-test 區過小／被其他層擋住（`pointer-events`）。  
2. 教學狀態機只認「特定卡 → 特定槽」卻沒有高亮正確槽。  
3. 觸控／滑鼠座標轉換錯誤（尤其直式手機框 + 縮放）。  
4. 失敗後沒有 retry／skip，卡在 `tutorialStep` 永不前進。

**具體改法**

#### A. 教學狀態機重寫（必做）
```
states: intro → highlight_card → drag_hint → drop_success → explain → done
```
- 每步只允許一種正確操作；錯誤時 **短暫** 提示「試下拖去發光嗰格」，**2 秒後自動收回**，不要永久「呢個位仲未啱」。  
- `done` 後寫入 `flags.rumorTutorialDone = true`，之後永不重播（除非設定「重看教學」）。

#### B. 明確視覺指引（必做）
- 正確 drop 槽：脈衝動畫 + 虛線框 + `aria`／輔助文字「拖去呢度」。  
- 正確卡片：外框高亮；其他卡 `opacity: 0.4` 且教學期間不可拖（或拖了也彈回）。  
- 拖曳中：slot 在 pointer enter 時變色（valid／invalid）。

#### C. 輸入相容（必做）
- 同時支援：mouse、touch、pointer events；`preventDefault` 避免頁面捲動搶手勢。  
- 用 slot 的 `getBoundingClientRect()` 做包含判斷，容錯 padding ≥ 12px。  
- 若偵測到拖曳開始後 8 秒仍未成功：顯示「幫你放好」按鈕（自動完成教學一步）+「跳過教學」。

#### D. 可跳過（必做）
- 教學 overlay 右上「跳過」；跳過等同 `done`，並給一句：「之後可喺選單 → 傳聞再試」。  
- Debug／QA：`?skipTutorials=1` 或現有 soft gate 一併跳過。

#### E. 遙測（建議）
記錄：`rumor_tutorial_start`、`drop_fail_count`、`skip`、`complete_ms`，方便確認是否仍卡住。

**實作檢查清單**
- [ ] 正確槽有明顯高亮  
- [ ] 錯放不會死鎖文案  
- [ ] 滑鼠 + 觸控皆可完成  
- [ ] 有跳過；跳過後可進入手動拼卡  
- [ ] 重整後若已完成不重播卡住狀態  
- [ ] 手機直式預覽框內拖曳不捲動背景

**驗收標準**
1. 新檔 10 次教學，成功率 100%（含只靠提示自動完成）。  
2. 故意錯放 5 次仍可繼續並完成。  
3. 跳過後傳聞功能可正常使用。

**優先級**：P0

### 3. 已完成主線仍可按「播事態」

**現象**  
金龍茶餐廳結算「先學做動作戲／先賺」後，仍顯示「播事態：…」；再按幾乎無回饋，與「只播一次」說明矛盾。

**根因假設**  
事態完成旗標有寫入結算，但地點 UI 仍用「有事態腳本」而非「未完成事態」來決定按鈕。

**具體改法**

#### A. 單一真相來源
```ts
incidentState: 'available' | 'locked' | 'playing' | 'completed' | 'cooldown'
```
- 結算成功 → `completed`。  
- 地點按鈕文案映射：  
  - `available` →「播事態：{短標題}」  
  - `completed` →「事態已完成」或完全隱藏  
  - `locked` →「事態未解鎖（條件…）」灰態

#### B. 禁止無效重播
- `onClick`：若 `completed`，不開對話；可選打開「回顧對白」唯讀。  
- 若設計允許 NG／多結局重玩：用明確「回顧／再選一次（會覆蓋結局）」並二次確認。

#### C. 資料遷移
- 舊存檔：若 log 已有該 incident 結算，載入時強制 `completed`。

**實作檢查清單**
- [ ] 完成後按鈕消失或改「已完成」  
- [ ] 點擊無空白 toast／無重開選項  
- [ ] 存檔重開狀態正確  
- [ ] 其他有事態的地點同樣邏輯（不要只修茶餐廳）

**驗收標準**  
完成任一事態後，該地點不再出現可播主按鈕；全地點掃描無「假可播」。

**優先級**：P1

### 4. 「還人情／送禮」無選擇 UI 卻宣告還清

**現象**  
庫存空仍可點「還人情／送禮」，toast「人情還清，無債一身輕」；人情債分頁仍有何生春季數、美兒已逾期等多筆。

**根因假設**  
按鈕 handler 直接 `clearAllDebts()` 或寫死 toast，未走「選債 → 選代價 → 扣資源 → 更新債單」。

**具體改法**

#### A. 完整流程 UI（必做）
1. 點「還人情」→ Modal：列出未清債（債主、事由、金額／禮物需求、是否逾期）。  
2. 玩家選 **一筆** 債。  
3. 選還法：  
   - 現金（顯示餘額，不足禁用）  
   - 指定禮物（顯示庫存數量；0 禁用）  
   - 若債允許「打招呼抵消」等特例，單獨標明。  
4. 確認 → 扣錢／扣物 → 該筆 `status='cleared'` → toast：「已還清：何生 · 春季數（-$X）」或「送出：{物品}」。  
5. 若仍有其他債：toast 不說「無債一身輕」。

#### B. 守衛條件
```ts
canRepay = debts.some(d => d.status==='open' && canAfford(d))
```
- 無可還：按鈕灰態，副文「未有可還嘅人情／禮物或現金不足」。  
- 庫存空且現金不足：不可進入「假成功」。

#### C. 「無債一身輕」文案條件
僅當 `openDebts.length === 0` 才可用該句；否則用精確句。

#### D. 逾期債
- 逾期要有後果（壓力＋／熟人好感－／封鎖某些通告），並在還清流程標紅。  
- 開局不應無因出現（見 #15）。

**實作檢查清單**
- [ ] 空手無法還清  
- [ ] 還一筆只清一筆  
- [ ] 人情債分頁即時更新  
- [ ] 扣費／扣庫存與 toast 一致  
- [ ] 存檔後狀態正確

**驗收標準**
1. 空庫存＋不足以還債的現金 → 無法出現「還清」成功 toast。  
2. 還清何生一筆後，美兒債仍在。  
3. 全部還清後才出現「無債一身輕」。

**優先級**：P0

### 5. 茶餐廳「$15 茶錢」聽八卦：錢未扣

**現象**  
點聽八卦／茶錢後存款仍 $12,000；只有「快啲記落手帳」類 toast，八卦內容當下看不清。

**具體改法**
1. `payTeaFee(15)`：若 `money < 15` → 拒絕並提示；否則 `money -= 15` 並播放金幣／存款 UI 動畫。  
2. Toast 必含數值：`「付咗茶錢 $15 · 餘額 $11,985」`。  
3. 八卦內容：Modal 或手帳新條目，至少留 4 秒可讀；可「寫入傳聞／情報」。  
4. 若 `softBehaviorGate` 令部分行動免費：UI 應顯示「（本次免費）」而不是寫 $15 卻不扣。

**驗收**  
連續點 3 次（若允許），存款遞減；內容可重看。

**優先級**：P1

### 6. 行動按鈕文案劇透結果

**現象**  
「還人情／送禮」副文已寫「何生心情好咗…」；主線選項按鈕內已寫結局句。

**具體改法**

  - 好：「跟張子駿磨戲（耗 1 日 · 壓力偏高）」

**驗收**

### 7. 地點「暫時未見熟人」vs 地圖熟人針／遠觀 NPC 矛盾

**現象**  
星河、獅子山、香江等進入地點後寫未見熟人，但地圖有熟人針或可見 NPC。

**具體改法**
1. 統一資料：`npc.presence = { locationId, visibleOnMap, interactable, reasonIfNot }`。  
2. 規則：  
   - 地圖針 ↔ `visibleOnMap`  
   - 地點內列表 ↔ `interactable && sameLocation`  
3. 若「遠觀得到但不可傾偈」：文案改「望到{名}，但佢忙緊／未開放傾談」，不要「未見」。  
4. 刷新時機：日推進、事態、時段變更時重算 presence。

**驗收**  
有針必能在對應地點解釋存在；「未見」只在真的無人時出現。

**優先級**：P2

**驗收**

### 9. 訓練結算排版黏在一起

**現象**  
如：「報名當日＝第一堂演技 +6壓力 +8電影組收工…」缺換行。

**具體改法**
1. 結算改結構化區塊，不要一條長字串：  
   - 標題：訓練名稱／日數  
   - 屬性變化列表（每項一行）：`演技 +6`  
   - 壓力／金錢／額外事件各一行  
2. 若必須字串拼接：用 `\n` 或 JSX `<br/>`／`<ul>`；CSS `white-space: pre-line`。  
3. 設計 token：數值用表格或 `Properties` 式排版。

**驗收**  
手機直式下每項變化獨立一行，不橫向溢出黏字。

**優先級**：P2

### 10. 週結算 flavor 與事實不符

**現象**  
通告完成 0／3，卻寫「何生說這週通告排得順」。

**具體改法**
1. flavor 改資料驅動：  
   ```ts
   if (gigsDone === 0) pick(lines.emptyWeek)
   else if (gigsDone >= gigsTarget) pick(lines.smooth)
   else pick(lines.partial)
   ```  
2. 禁止隨機池出現與 flag 矛盾的句子；寫單元測試：`(gigsDone, stress, debts) → flavor` 快照。  
3. 結算摘要先顯示事實數字，flavor 作補充。

**驗收**  
0 通告絕不出「排得順」；欠債逾期有對應語氣。

**優先級**：P1

### 11. 廣告通告天數邏輯怪

**現象**  
「每週 6 天／逢週一至六」但又「總天共 3 天」。

**具體改法**
1. 通告時間欄位拆清：  
   - `scheduleText`（給玩家看的檔期描述）  
   - `durationDays`（實際扣除行程日）  
   - `workdaysPattern`（可選，多日非連續）  
2. 顯示模板：  
   - 若扣 3 日：`「拍攝共 3 日（可分散於週一至六檔期）」`  
   - 避免同時並排兩個互相打架的「總天／每週天」。  
3. 行程機：報名時預扣／鎖定 `durationDays` 個工作日格。

**驗收**  
任一通告卡上，檔期描述與實際扣日一致；QA 抽 10 張通告無矛盾。

**優先級**：P2

### 12. 資源載入失敗（seal_junior/mid/senior.png）

**現象**  
Console：`seal_junior/mid/senior.png` `ERR_TIMED_OUT`（通告難度章）。

**具體改法**
1. 確認檔案存在於 `assets/...`；路徑大小寫、副檔名一致。  
2. 改可靠託管（同域相對路徑）；加 `onError` fallback（CSS 章或 emoji／文字 ★）。  
3. 建置時 asset 清單檢查；預覽環境用短 cache bust（`?v=`）但避免錯版號指空檔。  
4. 壓縮 PNG；避免過大圖導致 timeout。

**驗收**  
硬重整無 seal 404／timeout；斷網時仍有文字難度標。

**優先級**：P2

---

### 13. 中英文混雜文案（common／uncommon、sheet、romance）

**現象**  
商店 rarity 顯示 `common`／`uncommon`；庫存說明曾出現 `sheet`、`romance`。

**具體改法**
1. i18n map：  
   ```ts
   rarityLabel = { common: '普通', uncommon: '少見', rare: '稀有', ... }
   ```  
2. 禁止直接把 enum key render 上 UI；類型上用 `Rarity`，顯示用 `t('rarity.'+key)`。  
3. 全庫 grep：`common|uncommon|sheet|romance` 出現在 UI 綁定處一律改。  
4. 內容表「玩家可見欄」與「內部 id」分開。

**驗收**  
商店／庫存／提示全中文（或全粵語）；內部 id 只在 debug。

**優先級**：P2

### 14. 空「叮」toast

**現象**  
多處操作後頂部只出現「叮」無內容。

**具體改法**
1. Toast API 強制：`showToast({ title, body? })`；`body` 空則不顯示 toast，或開發模式丟 warning。  
2. 全域搜尋只傳音效／只傳「叮」的呼叫，補文案。  
3. 音效與文字解耦：`playSfx('ding')` + `showToast(msg)`。  
4. 預設文案表：依 actionType fallback（例如 `action.rest →「休息完畢」`）。

**驗收**  
玩一週流程無空白叮；自動化點擊冒煙測試截圖 toast 皆有字。

**優先級**：P2

---

### 15. 開局人情債敘事違和

**現象**  
Day1 已有「壓下負面新聞」「已逾期化妝品」等，角色尚未做過對應事。

**具體改法**
1. 新遊戲 `debts = []`，或只有 **1 筆教學債**（例如「向何生借車資 $50，三日內還」）。  
2. 逾期債改由事件產生：做過對應選擇／借貸後才寫入。  
3. 若要開局「背景債」：對白必須交代（開場旁白／母親留言／何生第一句）。  
4. 遷移：舊檔保留；新檔用新規則。

**驗收**  
新檔 Day1 債單與開場敘事一致；無「未發生事由」之逾期項。

**優先級**：P2

## 輕微問題

### 16. 選擇／鎖定事態仍顯示可點「播放」，再彈「暫未能報」

**改法**  
- 鎖定態按鈕改灰＋鎖圖示；副文直接寫鎖定條件。  
- `onClick` 對 locked 不觸發「暫未能報」通用通告錯誤（那是通告用語）；改「事態未解鎖」。  
- 可用／鎖定／完成三態視覺明顯分離（見 #3）。

**驗收**  
鎖定事態點擊不出現通告口吻錯誤；一眼可辨不可播。

**優先級**：P3

---

### 17. 行程日格文案黏連：「到處逛逛點此改行程」

**改法**  
- 日格結構：`主行動名` 一行；`操作提示` 用較淡、較小字另行，或長按／編輯模式才顯示「點此改行程」。  
- CSS：`flex-direction: column; gap: 2px`；避免字串直接相加無分隔。

**驗收**  
日格可讀，主行動與提示不黏成一句。

**優先級**：P3

---

### 18. 自動推進計劃日時，街頭表演結算易被跳過／不易察覺

**改法**  
1. 自動日結時，凡有 `resultCard` 的行動 → **暫停自動推進**，等玩家按「繼續」。  
2. 或結算改 queue：一天多個結果依序彈出。  
3. 週誌增加「本日結果」可重看。  

**驗收**  
街頭／咖啡店表演結算 100% 看得到；自動模式不吞卡。

**優先級**：P3

---

### 19. 手帳編輯中「已練 N 次」在連刷訓練時不即時更新

**改法**  
- 訓練確認後立刻 `setState` 更新 counter；勿等週結。  
- 若來自快取 props，改訂閱同一 store。  
- UI：`已練 {n} 次` 綁 reactive 狀態。

**驗收**  
連續報名 3 次訓練，數字每次 +1，無需重進畫面。

**優先級**：P3

---

### 20. 重整後短暫出現空白「地點」側欄

**改法**  
- 載入中顯示 skeleton／「載入行程…」，不要空「地點」標題。  
- hydrate 完成前不 render 地點面板，或保留上次 snapshot。  
- 修 race：map ready 與 location resolve 順序。

**驗收**  
硬重整 10 次無空白閃爍（或僅 skeleton）。

**優先級**：P3

---

### 21. 主線對白寫「剛從廠景收工」但遊戲日 1 才起步

**改法**  
- 開場對白改「未開工／剛入行／今日先去探路」。  
- 或開場事態設在「前史 Day0」已發生，日曆從 Day1 上班開始並在手帳顯示前史。  
- 內容審：凡時間副詞（剛、先、收工、昨夜）對照 `gameDay`。

**驗收**  
Day1 對白無「已收工」矛盾。

**優先級**：P3

---

### 22. softBehaviorGate 下多個「免費／無耗日」社交行動，與教學「傾談耗一日」不完全一致

**改法**  
1. 教學文案隨 gate 變化：  
   - gate on：`「試玩模式：部分傾談唔耗日」`  
   - gate off：維持「傾談耗一日」  
2. 每個行動按鈕標明代價：`耗 0 日（試玩）`／`耗 1 日`。  
3. README／預覽頁說明 softBehaviorGate 影響範圍。  
4. 正式版預設 gate off，教學與規則一致。

**驗收**  
教學句、按鈕代價、實際扣日三者一致。

**優先級**：P3（預覽／試玩模式仍建議修，免誤導設計判斷）
